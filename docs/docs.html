How Mimir works

A desktop shell in Rust, a React interface, a Python backend, and a model served locally by Ollama. Four processes on one machine, talking over localhost and nothing else.

Architecture

What runs where

When you launch Mimir, the Rust shell starts the bundled Python backend as a child process and points the webview at it. Nothing binds to a public interface.

The agent loop

Reason, act, observe

Every message runs through a ReAct loop that decides whether to answer directly or reach for a tool first.

  1. Gather context

    Hybrid retrieval pulls candidates from ChromaDB, ranks them again with BM25, fuses both orderings, and reranks the top pool with a cross-encoder. Alongside it go your recent turns, weak topics, recurring misconceptions, and — if the toggle is on — live web results.

  2. Stream and peek

    A single streaming call starts immediately. The first 80 characters are buffered to decide whether the model is answering or calling a tool. If it is answering, the buffer flushes and tokens continue live, so you see text in about a second rather than waiting for the whole response.

  3. Act, then synthesise

    If a tool was requested — quiz, flashcards, summarise, weak topics, web search — it runs, and a second streaming call turns the raw result into prose. Structured data is sent separately so the UI can render an interactive quiz card rather than JSON.

  4. Persist

    Both turns are written to SQLite and embedded into ChromaDB for future recall. These writes happen off the event loop and under a timeout — memory helps later recall, but it is never allowed to delay an answer.

From source

Building it yourself

You need Rust (stable), Node.js 20+, and Python 3.11+.

Development

git clone https://github.com/Sarthak-47/Mimir.git
cd Mimir

# backend
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m uvicorn main:app --port 8000

# frontend, in a second terminal
cd frontend
npm install
npm run dev

Production build (Windows)

The build script runs three stages: PyInstaller bundles the backend, the _internal tree is zipped to work around the NSIS 1000-file-per-folder limit, and Tauri produces the installer.

.\scripts\build.ps1

If you add a Python dependency, rerun PyInstaller before packaging. The zip is built from backend/dist/mimir-backend/_internal, so a stale dist silently ships an old dependency tree — a mistake that once cost a release.

Useful flags

CommandEffect
build.ps1 -CheckValidate every PyInstaller hidden import without building
build.ps1 -SkipBackendReuse the existing dist/, rebuild only the app
build.ps1 -DebugDebug build, no minification
Configuration

Settings and diagnostics

Adjustable at runtime

  • Model — any model installed in Ollama, listed with sizes
  • Temperature — lower for factual recall, higher for exploration
  • Context window — raising it costs VRAM
  • Quiz length and difficulty
  • Pomodoro intervals

Persisted to user_settings.json beside your data.

Health endpoints

With Mimir running, both are plain GETs on localhost:8000:

  • /health — is Ollama reachable, is the model pulled
  • /api/system/selftest — times each pipeline stage under its own timeout and names the one that fails

The packaged app buffers stdout, so selftest is the fastest way to see inside a build that is misbehaving.

Questions

Reasonable objections

Why local, when hosted models are better?

They are better. The trade is deliberate: your notes, your scores, and every question you were embarrassed to ask stay on your disk, and there is no bill or rate limit. For explaining course material you already own, a 9B model with your documents in context is closer to a hosted model than the parameter counts suggest.

Can I use a different model?

Yes. Anything in Ollama — pick it from Settings. Smaller models are faster and weaker; larger ones are slower and sharper. The default is chosen to fit an 8 GB GPU.

How accurate is it?

On material you have uploaded, well grounded — answers come from your documents. On general facts it has a training cutoff and will occasionally state something outdated with confidence. That is what the WEB toggle is for: with it on, Mimir searches first and answers from results rather than memory.

Does it need internet at all?

No. Everything except web search and the update check works offline. Web search ships off; you switch it on per session.

Is my data recoverable if I reinstall?

Yes — data lives outside the install directory, so updates and reinstalls leave it untouched. Back up the data folder named on the privacy page and you have everything.

Can I contribute?

Please. The repository is on GitHub with CI running the backend suite. Issues and pull requests are welcome.
