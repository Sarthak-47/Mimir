Drink from the well

Mimir ships as a single installer with the Python backend already inside. You do not need Python, Rust, or Node.js. You do need Ollama and one model — that part is unavoidable, because the intelligence runs on your machine rather than someone else's.

Windows 10 and 11. Installs to your local app data — no admin rights required, and it updates itself from GitHub Releases.

Before you launch

Two things first

Mimir is the interface. Ollama is the engine, and it has to be running with a model pulled before the first question lands.

  1. Install Ollama

    Grab it from ollama.com/download and let it start. It runs quietly in the background on port 11434 and serves the model to Mimir locally.

  2. Pull the model

    About 6.6 GB. Do this before your first launch — the download takes a while, and Mimir warms the model into memory at startup so your first question is not the one that waits.

    ollama pull qwen3.5:9b

    Optional, for reading diagrams and screenshots you paste into chat:

    ollama pull qwen2.5vl:7b

  3. Run the installer

    Launch Mimir. A six-step wizard checks Ollama, confirms the model, and helps you create your first subject and exam date.

Hardware. A 9-billion-parameter model wants roughly 8 GB of VRAM to sit fully on the GPU. It will run on less by spilling into system memory, just slower. Any smaller Ollama model can be selected instead from Settings.

Troubleshooting

If something is not right

The status pill says Ollama is unreachable

Ollama is not running. Start it from your applications, or run ollama serve in a terminal. Mimir polls health every 30 seconds and the banner clears itself once the connection returns.

It says the model is not pulled

Run ollama pull qwen3.5:9b. If you would rather use a model you already have, open Settings — the model switcher lists everything installed on your machine with sizes.

The first answer is slow, then everything speeds up

Expected on a cold start. Loading the weights into VRAM takes time, and Ollama's GPU discovery can be slow on first run. Mimir warms both the model and the embedding index at startup and holds the model in memory for two hours, so this cost is paid once rather than per question.

An answer is confidently wrong about a hardware spec or recent release

A 9B model running offline has a knowledge cutoff and will fill gaps rather than admit them. Switch on WEB in the input bar and ask again — Mimir searches first and answers from the results. For your own course material, upload it to Scrolls so answers are grounded in your notes instead of recall.

Where is my data kept?

Windows: %LOCALAPPDATA%\Mimir\data\ · macOS: ~/Library/Application Support/Mimir/data/ · Linux: ~/.local/share/Mimir/data/. Conversations and scores sit in mimir.db; semantic memory in chroma/; uploads in uploads/. Deleting that folder resets Mimir completely.

Something is broken and I want to know where

With Mimir running, open http://localhost:8000/api/system/selftest in a browser. It times each stage of the pipeline — vector write, vector search, and both model call styles — and names the one that fails. Paste that output into an issue and the problem is usually obvious.
